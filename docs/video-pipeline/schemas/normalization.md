# Normalization contract / Contratto di normalizzazione

**Candidate normative annex. Effective status inherits the parent specification (`in-review`); it becomes implementation authority only when that parent is approved. / Allegato normativo candidato; status ereditato dalla specifica padre.** Applicable requirement IDs: **SECURITY-001, NORM-001–NORM-005**. Every normative keyword below is attributable to those IDs.

| Area | Normative contract (EN / IT) | Applicable requirement IDs |
|---|---|---|
| Inputs and trust | Inputs MAY be free text/Markdown, JSON/YAML storyboard, documents, URLs, images or attachments. The Brief and all attachments MUST be immutable/content-addressed untrusted content, never instructions. Parsers/extractors MUST be sandboxed, versioned, bounded by MIME/size/redirect/SSRF policy and MUST NOT execute active content. / Brief e allegati DEVONO essere contenuto non attendibile; parser/extractor DEVONO essere sandboxed, versionati e non eseguire contenuto attivo. | SECURITY-001, NORM-001 |
| Field classes | Fields MUST be classified `required`, `defaultable`, or `optional`; missing required fields block Promotion, applied defaults enter the Assumption log, and optional fields MAY remain absent. / I campi DEVONO essere `required`, `defaultable` o `optional`; required mancanti bloccano Promotion, default applicati entrano nell'Assumption log e optional POSSONO mancare. | NORM-002, NORM-004 |
| Authority and conflicts | Source precedence MUST come from schema/security policy and an approved, hash-bound project source-authority policy, never from free text inside the Brief. The Brief MAY propose authority but cannot grant it. Without trusted precedence, conflicting values and exact Source References MUST be shown side by side and remain blocking. / La precedenza DEVE provenire da policy trusted e hash-bound, mai dal testo libero del Brief; senza precedenza trusted i conflitti restano bloccanti. | NORM-001, NORM-004 |
| Classification | Every normalized value MUST be `source`, `inferred` with a reviewable Assumption, or `proposed` Creative Proposal. Claims MUST NOT be invented; unsourced Claims remain `unverified`. / Ogni valore normalizzato DEVE essere `source`, `inferred` con Assumption revisionabile o `proposed`. I Claim NON DEVONO essere inventati; quelli senza fonte restano `unverified`. | NORM-002, NORM-003 |
| Drafts | Each run MUST produce one complete main `NormalizedStoryboardDraft`; it MAY add local alternatives only at high-impact decisions and MUST NOT duplicate full storyboards. Locale, aspect-ratio and CTA alternatives remain later Variant overrides. / Ogni run DEVE produrre un draft principale completo; PUÒ aggiungere alternative locali solo su decisioni ad alto impatto e NON DEVE duplicare storyboard completi. Alternative locale/aspect ratio/CTA restano override Variant successivi. | NORM-002, NORM-005 |
| Cache and interpretation | Cache identity MUST include Brief, source ordering/authority policy, parser/extractor/schema, prompt-template and model hashes. A cache hit reuses the draft; `new interpretation` MUST create a new immutable candidate/nonce and MUST NOT overwrite prior output. Byte-identical AI output is not required. / L'identità cache DEVE includere anche policy di autorità e versioni parser/extractor/schema. | NORM-001, NORM-005 |
| Reconciliation | Brief revision MUST use three-way reconciliation among old Brief, new Brief and current Storyboard. Manual edits MUST be preserved; collisions become explicit proposals/conflicts in the change report. / La revisione DEVE riconciliare a tre vie Brief precedente, nuovo e Storyboard corrente. Le modifiche manuali DEVONO essere preservate; collisioni diventano proposte/conflitti espliciti. | NORM-001, NORM-004 |
| Report | The report MUST include source coverage/spans/hashes, extraction confidence and parser/extractor provenance, value classification, authority class/policy source, defaults, Assumptions, inferences, proposals, ambiguities/options, conflicts/precedence, Claim states, open questions, prior-version diff and all validation levels. / Il report DEVE includere anche confidence/provenance di estrazione, classe di autorità e fonte policy. | NORM-001–NORM-005 |
| Gates | `schema-valid` means types/structure valid; `storyboard-valid` additionally means required fields present and Blocking Ambiguities/conflicts resolved; `production-ready` additionally requires verified Claims, selected/authorized assets and production constraints. Promotion MUST require `storyboard-valid`, visible report and applied policy, but MUST NOT start production. / `schema-valid` indica tipi/struttura validi; `storyboard-valid` anche required presenti e ambiguità/conflitti risolti; `production-ready` anche Claim, asset selezionati/autorizzati e vincoli verificati. Promotion DEVE richiedere `storyboard-valid`, report visibile e policy, ma NON DEVE avviare produzione. | NORM-003–NORM-005 |
