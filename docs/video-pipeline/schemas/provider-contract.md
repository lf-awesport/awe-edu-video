# Provider contract conceptual contract / Contratto concettuale provider

**Candidate normative annex; transport-neutral (CLI, MCP or future adapter). Effective status inherits the parent specification (`in-review`); it becomes implementation authority only when that parent is approved.** Applicable requirement IDs: **PROVIDER-001–PROVIDER-005, MODEL-005, COST-005, RIGHTS-001, ASSET-003**. Every normative keyword maps to those IDs.

| Record/area | Normative contract (EN / IT) | Applicable requirement IDs |
|---|---|---|
| CapabilitySnapshot | MUST bind provider, observed time, capability/model/schema hashes, constraints and redacted raw ref; exact immutable snapshot is pinned. / DEVE legare provider, tempo, hash capability/modello/schema, vincoli e raw ref redatto; snapshot immutabile pin. | PROVIDER-002 |
| Intent | MUST declare media type plus duration, aspect ratio, quality/resolution, audio presence/mode and hard/soft constraints. Semantic references MUST declare role (`style|subject|composition|motion|first-frame|last-frame|audio`) and authorized Asset hashes; continuity bundle MUST carry identity/environment/gaze/position/palette/light/motion/UI state. / DEVE dichiarare intent completo, reference semantiche e continuity bundle. | PROVIDER-002, MODEL-005 |
| Preference vs pin | Provider/model fields are optional preferences unless explicitly marked hard constraints. V1 MUST select only within an adapter/provider scope already authorized by the Execution Plan; model alternatives inside that scope MAY be exposed, but cross-provider switching MUST require a new plan/review. An unavailable hard constraint MUST fail. / V1 DEVE selezionare solo nel provider scope autorizzato; cambio provider richiede nuovo piano/review; hard constraint indisponibile fallisce. | PROVIDER-002 |
| Plan and economic binding | Immutable technical Plan MUST bind Intent/request/capability hashes, exact provider/model/schema/parameters and degradation. Economic evidence MUST distinguish dated `PriceObservation`, request-scoped `UnitQuote` or `BatchQuote`, and per-Candidate `QuoteBinding`. Every planned Candidate MUST have a fresh binding, but this does not require one remote quote call per Candidate when provider scope explicitly covers quantity. Input/capability/schema/model/price/quantity change or expiry MUST invalidate economic authorization and Plan application, not necessarily the unchanged technical plan. / Piano tecnico e binding economico DEVONO restare distinti; ogni Candidate ha binding fresco, non necessariamente una chiamata remota separata. | PROVIDER-002, PROVIDER-003, COST-005 |
| Reservation/submit | Reservation MUST bind QuoteBinding, applicable Budgets and maximum before submit. Persisted SubmissionIntent MUST identify Candidate/request/technical-plan/capability/economic-binding/Reservation/authorized-reference hashes, nonce and any idempotency/reconciliation keys before network action. The adapter MUST NOT reconstruct parameters from mutable live state. / Reservation e SubmissionIntent completi DEVONO precedere submit; l'adapter NON DEVE ricostruire parametri da stato mutabile. | PROVIDER-003, PROVIDER-004 |
| Retry semantics | Transport connect/read/poll/download retries MAY retry the same idempotent operation with bounded backoff. A potentially chargeable new submit MUST NOT be inferred from transport failure; missing/uncertain receipt enters `reconciling` and requires provider lookup or authorized new Candidate/nonce/Quote/Reservation. / Retry trasporto POSSONO ripetere la stessa operazione; nuovo submit oneroso NON DEVE essere implicito. | PROVIDER-004 |
| Reconcile/poll/cancel | Poll MUST normalize `queued|running|succeeded|failed|cancelled|unknown` while retaining redacted raw snapshots. Reconcile MUST return `matched|not-found-authoritative|ambiguous|unsupported|unknown`; absence from a non-authoritative history MUST NOT prove no submit. Cancel is optional: `unsupported` MUST be explicit, and accepted cancellation MUST remain reconciling until terminal state and charge are known. / Poll e reconcile DEVONO conservare incertezza; assenza da history non autorevole NON prova mancato submit; cancel resta da riconciliare. | PROVIDER-001, PROVIDER-004 |
| Materialization | Success MUST download into temporary storage, reject redirects/origins outside policy, and verify expected MIME/container, duration tolerance, dimensions/aspect, codec/streams, size and complete decode before SHA-256 and atomic Blob/Asset commit. Mismatch MUST fail and preserve diagnostic evidence without selection. / Il successo DEVE essere materializzato atomicamente con verifiche complete. | PROVIDER-005 |
| Candidate | Candidate MUST retain immutable ID/hash, request/intent/plan/capability/Quote/Reservation/SubmissionIntent/job lineage, materialized Blob/Asset hashes, provider/model/schema/parameters/references, terms and Rights/Consent refs, timestamps, status, quoted/reserved/actual/refunded/unknown cost and redacted raw refs. Candidate MUST remain separate from Selection and Approval. / Candidate DEVE conservare lineage, diritti e costo effettivo completi e restare separata dalle decisioni. | MODEL-005, ASSET-003, RIGHTS-001, PROVIDER-005 |

Higgsfield is one adapter. The observed v1 transport is the official CLI; MCP remains an unverified candidate transport and MUST pass the same contract/parity suite before substitution. Authentication remains an external credential profile; signed URLs, secrets and account balances MUST NOT enter portable records. / Higgsfield è un adapter; CLI è il transport v1 osservato, MCP resta candidato non verificato e DEVE superare contract/parity test. URL firmati, secret e saldi NON DEVONO entrare nei record portabili. Invalid non-normative stale-Quote lifecycle fixture: [E02](../examples/provider-lifecycle.json).
