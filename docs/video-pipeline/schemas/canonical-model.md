# Canonical model conceptual contract / Contratto concettuale modello canonico

**Candidate normative annex; not a compilable schema. Effective status inherits the parent specification (`in-review`); it becomes implementation authority only when that parent is approved.** Applicable requirement IDs: **MODEL-001–MODEL-005, AUDIO-001, ASSET-001, PROVIDER-002, RENDER-003**. Every normative keyword maps to those IDs. All records MUST carry `schemaVersion`; authored identity is a project-unique stable ID, immutable artifacts additionally have content hash/version. Owners named below are semantic aggregate owners, not people. / Allegato normativo candidato; status ereditato dalla specifica padre.

| Entity | Ownership; required refs / Proprietà; riferimenti required | Mutability, authority, cardinality/lifecycle invariant / Mutabilità, autorità, cardinalità-lifecycle | Applicable requirement IDs |
|---|---|---|---|
| Project | Root owns manifest refs, default locale/profiles and one-or-more source Briefs. / Root possiede riferimenti, default e uno-o-più Brief. | Manifest is versioned authority; no secrets/runtime. One Project has 0..n immutable Storyboard revisions and 0..1 current promoted revision; a new project MAY have none. / Manifest versionato, niente secret/runtime; 0..n revisioni e 0..1 promossa corrente. | MODEL-001, MODEL-002 |
| Brief / Draft / Storyboard | Project owns immutable Brief; Draft refs Brief/policy/model/report; promoted Storyboard refs source Draft/Report and owns exactly one Master. | Brief/Draft candidates and promoted revisions are immutable; Draft is never authority. Each Variant is bound to the exact Storyboard/Master revision it extends. / Tutti immutabili; Draft mai autorità; Variant legata alla revisione esatta. | MODEL-001 |
| Master | Storyboard owns exactly one Master; it refs BrandKit, Policy/Production/Output Profiles and semantic scripts. | Versioned creative authority; owns ordered 1..n Scenes and 0..n Transition edges; never mutated by Variant. / Autorità creativa versionata. | MODEL-001, MODEL-004 |
| Scene | Master owns stable ID/order, requested rational duration and 0..n Layers. | Relative-time narrative/approval unit; requested duration is authored intent. Draft/schema MAY contain no Layers, but compile MUST require renderable content or an explicit typed blank/placeholder. Build-resolved timing belongs to Production Lock/RenderPlan and MUST NOT silently mutate the promoted Storyboard. / Unità narrativa; durata richiesta è intent; timing risolto è di build e non muta silenziosamente lo Storyboard. | MODEL-001–MODEL-003 |
| Layer | Scene owns stable ID, core/plugin type, relative start/duration and content/asset/generation ref. | Exactly one content mode; bounded by scene unless explicit transition participation; cannot cause side effects. / Un solo modo contenuto; bounded; nessun side effect. | MODEL-001–MODEL-003 |
| Core Layer types | `footage|image|text|audio|caption|ui|shape|effect`; each refs typed semantic content and renderer capability. | Core schema is provider-neutral. Plugin types MUST use collision-safe `plugin:<owner>/<type>@<schema>` plus declared schema/renderer/capability/fallback; provider-specific parameters MUST live in versioned `provider:<name>` namespace and core MUST NOT depend on them. / Tipi core neutral; plugin/provider namespace dichiarati. | MODEL-001, PROVIDER-002 |
| Transition | Master owns ID, exact `from`/`to` adjacent scene refs, rational duration, `overlap|addition`, affected layers. | Edge, not Scene; no cycles/implicit overlap. Changes recompute resolved global timing. / Edge senza cicli/overlap implicito. | MODEL-001, RENDER-003 |
| Variant | Storyboard revision owns ID/version, exact Master hash, locale/output refs and 0..n stable-ID override operations. | Derived authority; overrides MUST NOT copy or mutate Master and unresolved/missing target fails. / La revisione Storyboard possiede la Variant; override derivato non duplica/muta Master. | MODEL-001, MODEL-004 |
| BrandKit | Project owns ID/version, semantic tokens, logo/font/asset refs and brand rules. | Central authority; Layers MAY declare explicit local override subject to policy. Assets remain separate. / Autorità centrale; override locale esplicito. | MODEL-001 |
| Policy Profile / Production Profile / Output Profile | Project refs versioned profiles. Policy governs approvals/rights/budget/retention; Production governs candidate/fallback/validation depth; Output governs dimensions/aspect/fps/codecs/audio/captions/layout. | Policies MUST NOT alter Storyboard intent or waive invariants; Output frames derive from rational seconds. One build resolves exactly one of each applicable profile. / Policy non altera intent; un profilo applicabile per build. | MODEL-001, MODEL-003 |
| Script / LocalizedScript / Utterance / VoiceProfile | Project owns versioned master Script units; each LocalizedScript refs one Script+locale; it owns 1..n Utterances; VoiceProfile refs locale/pronunciation/consent constraints. | Script is semantic, not audio. Localized wording/timing may differ but maps master units; Utterance is smallest coherent independent recording unit. / Script semantico; mapping locale; Utterance minima. | MODEL-001, AUDIO-001 |
| GenerationRequest | Layer/audio owner owns immutable request ID/hash, Intent, references/continuity and optional authored provider/model preference or hard constraint. | One request yields 0..n immutable Candidates; absence of a preference MUST NOT authorize automatic cross-provider selection. Operational resolution/pins live in Execution Plan/Production Lock. / Una request produce 0..n candidate; assenza preference non autorizza selezione multi-provider. | MODEL-005 |
| Provider Job / output | Runtime State owns opaque job lineage; a job MAY yield 0..n typed provider outputs. | Job state is volatile. Each output role and its mapping to Candidate MUST be explicit; batches MUST NOT collapse distinct attempts, costs or provenance. / Job volatile; output role e mapping Candidate espliciti. | MODEL-005, PROVIDER-004, PROVIDER-005 |
| Candidate | GenerationRequest owns generated/imported candidate ID/version/hash, request/plan/job/output lineage, 1..n typed Blob refs only when declared by contract, provenance/rights/cost. | Immutable evidence; 0..n per request; materialized/verified before selection eligibility. / Immutabile, materializzata/verificata. | MODEL-005 |
| CandidateSelection | Layer or Utterance owner records ID/version, exact Candidate+artifact/dependency hashes, actor/policy/time. | Append-only decision distinct from Approval; at most one current selection per selection slot, replacement supersedes. / Decisione distinta; una current per slot. | MODEL-005 |
| Blob | Asset Store owns immutable SHA-256 bytes and technical metadata only. | Globally deduplicable 1 Blob to 0..n Assets; no project meaning/rights. / Dedupe globale, nessun significato/diritto. | ASSET-001, MODEL-005 |
| Asset and selected Asset binding | Project owns Asset ID/version, exact Blob hash, purpose/provenance/rights/sensitivity/lineage. A selected binding refs Layer/Utterance slot + current CandidateSelection + Asset hash. | Asset metadata is append-versioned while Blob is immutable. Final render requires exactly one current selected binding for each required asset slot; URL/path is never binding authority. / Metadata versionati, Blob immutabile; binding esatto obbligatorio. | ASSET-001, MODEL-005 |

Desired specification and volatile execution remain separate. Concrete provider/model/schema resolution, selected Candidates/Assets, build-resolved timing, policies, approvals, costs and dependency/provenance hashes MUST be frozen in the **Production Lock defined by [manifests](manifests.md)**; volatile poll state and raw job payloads remain Runtime State. / Specifica desiderata e stato volatile restano separati; risoluzioni e timing di build DEVONO essere congelati, mentre poll/job raw restano Runtime State.
