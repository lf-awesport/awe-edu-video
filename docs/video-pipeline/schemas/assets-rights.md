# Assets, provenance, rights and consent / Asset, provenienza, diritti e consenso

**Candidate normative annex. Effective status inherits the parent specification (`in-review`); it becomes implementation authority only when that parent is approved.** Applicable requirement IDs: **ASSET-001–ASSET-003, RIGHTS-001–RIGHTS-003, RELEASE-005**. Every normative keyword maps to those IDs.

| Area | Normative contract (EN / IT) | Applicable requirement IDs |
|---|---|---|
| Blob/Asset | Blob MUST be immutable SHA-256 bytes with technical metadata; path/name/URL are aliases. Asset MUST be a project-scoped record with origin/source ref/acquisition time/actor/method, purpose, sensitivity, cost, MIME/codec/dimensions/duration, rights and lineage. One Blob MAY back isolated Assets. / Blob DEVE essere byte immutabile SHA-256; Asset DEVE contenere metadata completi project-scoped; un Blob PUÒ supportare Asset isolati. | ASSET-001 |
| AI provenance | Generated assets MUST record provider/model/version/schema, prompt/parameters, semantic references, job, applicable terms/account-plan metadata and available C2PA, without claiming uniqueness or clearance. URL/stock imports MUST be materialized with URL, acquisition time/hash and terms snapshot/ref. / Asset generati DEVONO registrare la provenienza completa senza promettere unicità/clearance; import URL/stock DEVONO essere materializzati. | ASSET-003 |
| Sensitivity/quarantine | Sensitivity MUST be `public|internal|restricted`. Restricted bytes MUST NOT enter Git/log/shareable bundles. Incomplete provenance/rights MUST be `quarantined|internal-preview-only`; unknown rights MUST NOT be inferred. / Sensibilità DEVE usare gli stati; restricted NON DEVE entrare nei canali condivisibili; incompletezza DEVE quarantinare e diritti ignoti NON DEVONO essere inferiti. | RIGHTS-002, RIGHTS-003 |
| Grants | Rights Grant MUST specify holder, licence/contract evidence, uses/media/territories/duration, attribution placement/text, sublicensing, modification and AI constraints. Consent Grant MUST separately identify subject, likeness/voice/cloning/transformation, purpose/media/territories/duration/revocability. Restricted evidence MUST use hash + secureRef. / Grant DEVONO contenere i campi indicati ed evidence restricted DEVE usare hash + secureRef. | RIGHTS-001, RIGHTS-002 |
| Transformations | Crop/transcode/upscale/grade/composite MUST create a new Blob and Asset linked to parents/tool/version/params/actor. Derived constraints MUST be the intersection of parent constraints plus any stricter additions and MUST NOT expand rights. / Ogni trasformazione DEVE creare nuovi record e intersecare, NON ampliare, i diritti. | ASSET-002 |
| Revocation/obligations | Expiry/revocation MUST propagate blocked/non-releasable and create an impacted-deliverables report. Each Grant MUST declare consequence policy such as `block-new-release|withdraw-controlled-distribution|delete-by-deadline|review-required`; external copies not controlled by the pipeline remain tracked obligations, never falsely reported as withdrawn. / Revoca DEVE propagare e creare obblighi espliciti anche per deliverable già distribuiti. | RIGHTS-003 |
| Retention/erasure | Referenced Blobs MUST NOT be automatically deleted. Logical Asset erasure, access/cryptographic revocation and physical Blob deletion are distinct. Physical deletion MUST use a consistent global reference/replica inventory, recheck the last authorized reference, honor retention/legal hold, and record backup/export obligations. Rebuild MUST reproduce `erased/unavailable` from a minimal policy-authorized non-personal tombstone. / Erasure logica, revoca accesso e cancellazione fisica sono distinte; delete richiede indice globale, replica inventory e tombstone deterministico. | RIGHTS-003 |
| GC/dedupe/export | GC MUST plan/report, verify global references/retention/legal hold, quarantine before deletion, require confirmation and MUST NOT run during build/render. Physical dedupe MAY occur only at Blob level. Exports MUST include only necessary authorized material, redact destination-specific metadata and register destination obligations. / GC DEVE verificare riferimenti globali; export DEVONO registrare obblighi di destinazione. | ASSET-001, RIGHTS-002, RIGHTS-003 |
| Usage | Every deliverable MUST have an Asset Usage Manifest mapping every visible/audible Asset to variant/scene/layer/time/frame, transformations and current grants, enabling final-frame-to-source lineage. / Ogni deliverable DEVE avere Usage Manifest completo e risalibile. | RELEASE-005, ASSET-002 |
